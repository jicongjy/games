# 작업 기록 (할머니의 마을 노트)

무엇을 왜 했는지 적는 기록이다. 규칙의 자세한 내용과 숫자는 `기획.md`에 있다. 새 작업을 하면 맨 위에 추가한다.

## 2026-11-19 규칙 통일: 다섯 의뢰를 모두 일꾼 규칙으로

- 작업 브랜치: `small-town/rules-unify` (main에는 아직 병합하지 않았다)
- 시작 전 상태: 일꾼 규칙은 1번 의뢰와 튜토리얼에만 있었고, 2~5번은 옛 규칙이었다(기획.md에도 "시험 중, 첫 번째 의뢰만"이라고 적혀 있었다).
- 정한 것: 사용자가 "일꾼 규칙으로 통일"(A안)을 골랐다. 의뢰 2번부터 하나씩 옮기고, 의뢰마다 시뮬레이터(`tools/sim-work.js`)로 난이도를 본 뒤 브랜치에 커밋한다.

1번 의뢰 수치는 그대로다(규칙 무시 81%, 규칙대로 100%). 기획.md가 99%라고 적었던 것은 100%로 고쳤다.

### 시뮬레이터 확장
- `node tools/sim-work.js [의뢰 번호] [장날 요구량]`으로 1~5번을 모두 잴 수 있다.
- 자동 플레이는 단순하다. 같은 의뢰라도 일꾼을 어디에 쓰는지 정하는 방식에 따라 통과율이 0%에서 90%대까지 바뀌었다. 난이도의 방향을 보는 용도이고, 실제 난이도는 직접 해 봐야 안다.

### 확인한 방법
- 브라우저(Playwright, 390×664)로 의뢰마다 새 규칙의 거절 문구, 칸 표시, 실패 문구를 확인했다. JS 오류는 없었다.
- 안 한 것: 실제 휴대폰, 세로 560 안팎의 작은 화면, 사람이 직접 한 플레이 기록.

### 남은 일
1. 사람이 직접 다섯 의뢰를 해 보고 막힌 곳, 재미있던 곳을 기록한다.
2. 유물 5종은 일꾼 규칙에서 아직 쓰이지 않는다. 보상으로 받기만 한다.
3. 옛 규칙 코드는 지우지 않기로 했다. 위치와 보관 브랜치는 `옛규칙-보관.md`에 있다.
4. main 병합은 아직이다. 병합하면 공개 사이트가 바뀐다. 기존 저장 데이터(조각, 별)와 호환되는지 먼저 확인해야 한다.

### 작업 중 알아 둔 것
- 훅이 "미푸시 N개, 원격 브랜치 없음"이라고 알리는데, 원격 브랜치는 있었고 미푸시는 마지막 커밋 하나뿐이었다. main과 비교해 세는 것으로 보인다.
