# 옛 규칙 코드 보관

2026-11-19에 다섯 의뢰가 모두 **일꾼 규칙**으로 옮겨져서(작업기록.md 참고), 아래 두 규칙의 코드는 지금 어떤 의뢰에서도 쓰이지 않는다. 지우지 않고 파일에 그대로 두었고, 별도로 옮기기 전 상태를 브랜치로 보관했다.

## 1. 보관 브랜치 (옮기기 전 상태 그대로)
- 브랜치: `small-town/archive-old-rules`
- 기준 커밋: `ed089c6` (main, 2026-11-17, PR #8 병합). 이 시점은 1번 의뢰와 튜토리얼만 일꾼 규칙이고, 2~5번은 옛 규칙이다.
- 이 브랜치는 수정하지 않는다. 옛 규칙을 다시 살리거나 비교하고 싶으면 여기서 꺼낸다.
- 꺼내 보는 법: `git show small-town/archive-old-rules:small-town/js/engine.js` 또는 `git checkout small-town/archive-old-rules`

## 2. 지금 파일에 남아 있는 곳
**옛 규칙(5×5 땅에 놓는 순간 한 번 발동, 짐 싸기)**
- `js/engine.js` 1~253줄: `ST.newGame`, `ST.canMove`, `ST.meets`, `ST.evaluate` 등
- `js/ui.js`: `vBuild`(짓기 화면), `vPack`(짐 싸기), `makeDraft`, `tutStep`(옛 튜토리얼 단계)
- `js/data.js`: 조각의 `desc`, 의뢰의 `goals`, `bonus`, `tip`, `lend`, `limit`, `ST.TUTOR`의 `order`

**날짜 규칙(하루에 조각 하나, 매일 밤 일함)**
- `js/engine.js` 255~458줄: `ST.days`(`D.*`)
- `js/ui.js`: `vDays`(날짜 규칙 화면)
- `js/data.js`: `DAILY`, `TAG`, `ST.EVENTS`, 1번 의뢰의 `days`

줄 번호는 2026-11-19 기준이라 파일을 고치면 달라진다. 이름으로 찾는다.

## 3. 아직 연결되어 있는 것
옛 규칙 코드는 의뢰에 `work`가 없을 때만 돈다(`js/ui.js`의 `newBoard`). 지금은 다섯 의뢰와 튜토리얼에 모두 `work`가 있어서 그 분기는 실행되지 않는다. 새 의뢰를 `work` 없이 만들면 옛 규칙으로 돈다.

## 4. 삭제할 때 같이 볼 것
지우기로 정하면 위 목록과 함께 `tools/sim.js`(옛 규칙 난이도 도구), `docs/기획.md`의 "날짜 규칙", "카드 겉면" 부분을 같이 정리한다. 지우기 전에 보관 브랜치가 원격에 있는지 먼저 확인한다.
